fix: resolve build type errors in link tracking logic

Problem Statement:
1. The recent overhaul to granular per-grant tracking introduced a scope resolution issue in `services/links.ts` where `migratedGifts` was block-scoped but referenced in an outer block.
2. The `giftBonus` variable name was mismatched after renaming to `remainingGiftLinks`.
3. The TypeScript compiler strictly enforced the `GiftQuota` interface resulting in missing `used` property compilation errors in the build step, preventing Vercel deployments from succeeding.

Fixes Implemented:
1. TypeScript Declarations: 
   - Explicitly added the `used?: number` property to the global `GiftQuota` interface in `types/index.ts` to reflect the new dynamic grant consumption logic.
   - Fixed inline interface definitions in `services/links.ts`, `services/grants.ts`, and `app/api/links/route.ts` to strictly type the new properties.
2. Block Scope & Variable Naming:
   - Elevated the scope of `migratedGifts` out of the localized block in `services/links.ts` to guarantee visibility during the write-back transaction.
   - Standardized `remainingGiftLinks` in calculating the effective limit, matching the new precise grant arithmetic.
3. Build Verification:
   - Ensured a clean, robust build via a local `npm run build` mimicking the Vercel edge runtime environment.
